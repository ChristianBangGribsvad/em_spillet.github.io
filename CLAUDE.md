## What the project is

A **football tournament prediction game** originally built for UEFA EURO 2024, now being
adapted for the **FIFA World Cup 2026** (starts June 11, 2026).

Participants fill out a Google Form before the tournament starts. Their predictions are
scored nightly against live results fetched from an API. Standings and visualisations are
published automatically as a static website via GitHub Pages.

**Live site:** https://christianbanggribsvad.github.io/wc-predictions.github.io/

## Full data flow

```
1. INPUT
   Google Form → "WC spillet 2026.csv"  (one row per participant, ~90+ columns)

2. HOURLY TRIGGER  (.github/workflows/daily.yaml)
   cron: "15 * * * *"  →  python main.py

3. API FETCH  (get_results.py)
   GET https://api.football-data.org/v4/competitions/WC/matches
   Headers: X-Auth-Token: <token>
   → Cached as results/data_N.pickle  (list of (match_id, score) tuples)
   → match_id format: "Group A Predictions [Mexico - South Africa]"
                   or "LAST_32 Predictions [Mexico - USA]"

4. EARLY-EXIT CHECK  (main.py)
   If new results == previous cached results → exit (no changes to commit)

5. SCORING  (eval_funcs.py)  — for each participant:
   eval_match_predictions()  →  2/5/10/15 pts per group match
   eval_groups()             →  5/7.5 pts per group winner prediction  ⚠ BROKEN for WC
   dk_finish()               →  15 pts for Denmark knockout round      ⚠ EURO-specific
   dk_goals_scored()         →  20 pts for Denmark total goals         ⚠ EURO-specific
   main.py (inline)          →  top scorer (20), final winner (25),
                                final loser (15), top scorer goals (10)
                                via HARDCODED COLUMN INDICES — ⚠ BROKEN for WC

6. PERSISTENCE
   data/user_dfs/{f_name}    ← pickle of 3-row DataFrame per participant
   data/group_dfs/{group}    ← pickle of date-indexed cumulative scores

7. VISUALISATION  (plot_funcs.py)
   plot_user()               → pages/user_plots/{f_name}.svg
   plot_group_progress()     → pages/group_plots/lines_{group}.svg
   plot_best_round()         → pages/group_plots/bars_{group}.svg  (day 2+)
   plot_standings()          → pages/group_plots/standing_{group}.svg

8. MARKDOWN GENERATION
   create_pages()            → pages/{f_name}.md  (one per participant)
   update_pages()            → index.md  (homepage)

9. GIT COMMIT & PUSH  (.github/workflows/daily.yaml)
   git add . && git commit ... || echo "No changes to commit"
   → GitHub Pages rebuilds Jekyll site automatically on push
```

## Participant data format

**CSV columns (in order):**
```
0:  Timestamp
1:  First name
2:  Last name
3:  Which team(s) do you belong to?       ← semicolon-separated if in multiple groups
4+: Group {X} Predictions [{Home} - {Away}]   ← one per group-stage match
    (72 columns for WC 2026: 12 groups × 6 matches)
    Group winner predictions:  "Group A 1st place", "Group A 2nd place"  (24 cols)
    Special predictions:       Final winner, final loser, top scorer,
                               top scorer goals, home country round, home country goals
```

**Derived columns added in main.py:**
- `f_name`: `FirstName_XX` (file-safe, first 2 chars of last name)
- `d_name`: `FirstName XX` (display name)

**user_df pickle structure (3 rows × N cols):**
- Row 0: participant's predictions
- Row 1: actual results (filled in by eval functions)
- Row 2: points earned per column

## Known issues / must-fix before WC 2026 launch

### 1. `eval_groups()` — hardcoded for 6 groups  🔴 Critical
**File:** `eval_funcs.py`
```python
for i in range(6):   # ← must be range(len(all_group_res)) or similar
    ...
    if i == 2:
        res2nd = "Denmark"   # ← EURO 2024 manual hack, must be removed
```
WC has 12 groups. This will `IndexError` at `i=2` if fewer than 3 groups are
present, and silently mis-score group 3 (index 2) for the whole tournament.

**Fix:** Replace `range(6)` with `range(len(group_winner_cols) // 2)`, and
remove the Denmark override entirely.

### 2. Hardcoded column indices for special predictions  🔴 Critical
**File:** `main.py` lines ~88–112
```python
user_df.iloc[0, 52]   # finale_winner prediction
user_df.iloc[0, 53]   # finale_loser prediction
user_df.iloc[0, 54]   # top scorer prediction
user_df.iloc[0, 55]   # top scorer goals prediction
```
The WC 2026 CSV has a different column count (72 group matches vs 24 for EURO,
plus 24 group winner cols vs 12). These indices will point to completely wrong
columns — silent data corruption.

**Fix:** Replace all `iloc[0, N]` references with named column lookups, e.g.:
```python
user_df.at[0, "FIFA World Cup 2026 final winner"]
```

### 3. API token hardcoded in source code  🟡 Security
**File:** `get_results.py` line 24
```python
headers = { 'X-Auth-Token': '242e02ff31ea497fbe4b85978fe70b81' }
```
Token is in a public GitHub repository. Should be stored as a GitHub Actions
Secret (`FOOTBALL_API_TOKEN`) and read via:
```python
import os
headers = { 'X-Auth-Token': os.environ['FOOTBALL_API_TOKEN'] }
```
Add to `.github/workflows/daily.yaml`:
```yaml
env:
  FOOTBALL_API_TOKEN: ${{ secrets.FOOTBALL_API_TOKEN }}
```

### 4. `eval_funcs.py` FutureWarning — will become a hard error  🟡 Pandas
**File:** `eval_funcs.py` line 14
```python
predictions_df.loc[len(predictions_df), predictions_df.columns] = ["-"]*len(...)
```
Sets string `"-"` into float64 columns. Currently a `FutureWarning`; will raise
`ValueError` in a future pandas version.

**Fix:** Cast the DataFrame to `object` dtype before adding mixed-type rows, or
add the rows separately with `pd.concat`.

### 5. Denmark-specific columns in CSV  🟡 WC adaptation
The EURO 2024 form had:
- "Which round does Denmark reach?"
- "How many goals does Denmark score in total?"

For WC 2026, decide whether to keep a "home team" concept (e.g. Denmark if they
qualify) or remove these columns entirely. The column names are used in
`dk_finish()` and `dk_goals_scored()` in `eval_funcs.py`.

### 6. `eval_groups()` only scores first 2 qualifier positions  🟠 WC rule change
In WC 2026, **3 teams per group qualify** (not 2). The top 2 advance directly;
the 8 best 3rd-place teams also advance to LAST_32. The current
`eval_groups()` only tracks 1st and 2nd place predictions, which is fine as long
as the form only asks for 1st/2nd. Verify with the WC 2026 form design.

### 7. `test_main.py` (old test) is EURO-specific and references missing file  🟠 Cleanup
References `test_results.pkl` (not in repo) and hardcodes EURO match counts.
Can be safely deleted or replaced by `test/test_pipeline.py`.

### 8. GitHub Actions uses outdated action versions  🟢 Low priority
```yaml
uses: actions/checkout@v2          # → should be @v4
uses: actions/setup-python@v2      # → should be @v5
uses: ad-m/github-push-action@master  # → pin to specific SHA
```

## Scoring rules reference

| Prediction type | Points |
|---|---|
| Exact score (both teams) | 15 |
| Correct outcome + one team's exact score | 10 |
| Correct outcome only (win/draw) | 5 |
| One team's exact score only | 2 |
| Group stage 1st AND 2nd correct | 7.5 each |
| Group stage 1st/2nd swapped, or one correct | 5 |
| Home country knockout round (exact) | 15 |
| Home country total goals (exact) | 20 |
| Top scorer (correct player) | 20 |
| Top scorer goals (exact) | 10 |
| Final winner (correct) | 25 |
| Final loser (correct) | 15 |
| Final winner/loser swapped | 10/5 |
